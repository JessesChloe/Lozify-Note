## 🛠️ 深度排查与踩坑记录总结 (Troubleshooting & Lessons Learned)

在本次大版本迭代与真机实测过程中，团队对一系列启动崩溃与偶发白屏问题进行了深度溯源与根治，相关经验总结如下：

### 坑 1：AndroidX Biometric 库与纯 Compose 架构冲突导致启动崩溃
- **现象**：启动即闪退，日志报错 `IllegalStateException: You need to use a Theme.AppCompat theme (or descendant) with this activity`。
- **原因**：引入的 `androidx.biometric:biometric` 库底层强依赖 Fragment 与 AppCompat 主题，而在纯 Jetpack Compose 应用中，Activity 使用的是 `android:Theme.Material.Light.NoActionBar`，导致底层对话框初始化时直接崩溃。
- **解决**：彻底移除 `androidx.biometric` 依赖，改用 Android SDK 原生的 `android.hardware.biometrics.BiometricPrompt`，使用 `try-catch` 和 `CancellationSignal` 进行纯原生沙盒化封装，100% 兼容任何 Compose 架构。

### 坑 2：Manifest 缺失生物识别权限导致 `SecurityException`
- **现象**：调用原生指纹 API 时闪退，抛出 `java.lang.SecurityException: Must have android.permission.USE_BIOMETRIC permission`。
- **解决**：在 `AndroidManifest.xml` 中完整补齐 `<uses-permission android:name="android.permission.USE_BIOMETRIC" />` 与 `<uses-permission android:name="android.permission.USE_FINGERPRINT" />`，并增加权限检查与 `try-catch` 降级兜底。

### 坑 3：Compose 1.6 下在根层级注入 `LocalLifecycleOwner` / `hiltViewModel()` 导致崩溃
- **现象**：启动即闪退，抛出 `CompositionLocal LocalLifecycleOwner not present`。
- **原因**：在 Jetpack Compose 1.6 (BOM 2024.06) 中，`androidx.lifecycle.compose.LocalLifecycleOwner` 无法在最外层 `setContent` 或 `HomeScreen` 根节点直接注入，调用即崩。
- **解决**：彻底移除根节点的 `LocalLifecycleOwner` 监听器，改用轻量化响应式状态管理 (`remember(isAppLockEnabled, appLockPin)`)，消除对外部脆弱生命周期注入的依赖。

### 坑 4：旧版本升级时 SharedPreferences 键值类型转换异常
- **现象**：覆盖安装老版本时，读取新配置项直接抛出 `ClassCastException` 崩溃。
- **解决**：将 `UserPreferencesManager` 中所有 `prefs.get*` 读取方法全部用 `try-catch` 包裹，遇类型冲突自动安全降级至预设默认值，杜绝老数据升级崩溃。

### 坑 5：导航路由 `TagEditScreen` 标签为空导致偶发白屏
- **现象**：在侧边栏点击编辑未置顶或计数为 0 的标签时，页面直接呈现纯白屏。
- **原因**：`HomeViewModel.allTags` 过滤了非置顶且计数为 0 的标签，导致 `NavGraph` 中寻址失败，`if (tag != null)` 判定为 false 且无任何 fallback Composable 渲染。
- **解决**：`HomeViewModel.allTags` 改为暴露全量标签流，并在 `LozifyNavGraph` 中增加了优雅的加载转圈兜底容器，彻底消除白屏。

### 坑 6：`HorizontalPager` 内嵌 `Column.verticalScroll` 导致长文本滑动卡顿
- **现象**：每日回顾卡片文本较长时，手指上下滑动非常生涩、只能勉强拖动。
- **原因**：横向 Pager 与纵向 `verticalScroll` 手势拦截发生冲突。
- **解决**：卡片内部全面重构为高性能的 `LazyColumn`，利用其内置的嵌套滑动连接（NestedScroll）与弹性回弹物理模型，恢复丝滑惯性滚动。
