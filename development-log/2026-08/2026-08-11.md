### Bug 2: HomeScreen.kt 类型推断错误（Line 319 & 383）
**报错信息：**
```
e: .../HomeScreen.kt:354:26 Cannot infer type for this parameter. Please specify it explicitly.
```

**根因分析：**
Kotlin 编译器在复杂的 lambda 嵌套场景下（特别是解构声明 `{ (title, relations) ->`）无法自动推断参数类型。

**解决方案 1: NoteCard 回调参数显式类型标注（Line 319）**
```kotlin
// ❌ 错误：隐式类型推断失败
onRelationsClick = { relations, title ->
    showRelationsDialog = Pair(title, relations)
}

// ✅ 正确：显式类型标注
onRelationsClick = { relations: List<NoteRelation>, title: String ->
    showRelationsDialog = Pair(title, relations)
}
```

**解决方案 2: LazyColumn items lambda 显式类型标注（Line 383）**
```kotlin
// ❌ 错误：隐式类型推断失败
items(relations) { relation ->

// ✅ 正确：显式类型标注
items(relations) { relation: NoteRelation ->
```

**解决方案 3: ModalBottomSheet 解构参数显式类型标注（Line 354）**
```kotlin
// ❌ 错误：解构声明缺少类型
showRelationsDialog?.let { (title, relations) ->

// ✅ 正确：显式类型标注
showRelationsDialog?.let { (title: String, relations: List<NoteRelation>) ->
```

## 踩坑总结与经验教训

### 🔥 核心教训：Kotlin Lambda 类型推断陷阱

**陷阱场景：**
1. **Lambda 嵌套层级过深**：Compose UI 中常见 `{ param1, param2 -> ... }` 嵌套在函数调用中
2. **解构声明**：`let { (a, b) -> }` 比普通 lambda 更容易触发推断失败
3. **泛型参数**：`List<NoteRelation>` 作为 lambda 参数时，编译器需要显式提示

**黄金规则：**
- ✅ **永远为 lambda 参数添加显式类型**，特别是：
  - 高阶函数回调（如 `onRelationsClick`）
  - Compose UI 的 `items { }` 等遍历函数
  - 解构声明的 `let { (a, b) -> }`
- ✅ **不要依赖 Kotlin 编译器的自动推断**，宁可冗余也不要隐式
- ✅ **修改代码后立即检查 import**，避免遗漏依赖

---

### 🛠️ 工程化改进建议

**防止低级错误的策略：**
1. **IDE 自动 import 优化**：启用 Android Studio 的 "Optimize imports on the fly"
2. **编译前自检清单**：
   - [ ] 新增 Composable 组件是否导入？
   - [ ] Lambda 参数类型是否显式？
   - [ ] Material3 组件是否完整导入？
3. **代码审查重点**：
   - 关注所有 `{ param ->` 是否需要 `: Type`
   - 关注所有 `let { (a, b) ->` 解构声明
