## 🛠️ 完成内容详解

### 1. 🌐 WebDAV 协议引擎 (`WebDavClient.kt`)
- **协议实现**:
  - 基于 OkHttp 构建轻量、鲁棒的 WebDAV 客户端，遵循 RFC 4918 标准；
  - 支持 HTTP Basic Authentication 认证与专用应用授权密码；
  - 封装标准与扩展请求动词：`PROPFIND`（深度 0/1 探测与文件列表查询）、`MKCOL`（层级目录递归创建）、`PUT`（流式上传）、`GET`（断点/流式下载）、`HEAD`（元数据探测）；
  - 智能错误分类：精确识别 HTTP 401（应用授权密码错误）、HTTP 403（权限不足）、HTTP 404（路径不存在）、网络超时与 SSL 异常，提供清晰友好的中文错误反馈。

### 2. ⚡ 双向增量数据合并与附件同步引擎 (`WebDavSyncManager.kt`)
- **远端文件布局**:
  ```
  /Lozify/
  ├── manifest.json              # 同步元数据（最后更新时间、版本号、设备信息）
  ├── data/
  │   └── notes_payload.json      # 结构化全量卡片、标签、关联与附件信息
  └── images/                    # 差异化图片资源池
      ├── img_1787030000_1.jpg
      └── img_1787030000_2.jpg
  ```
- **核心同步算法**:
  1. **LWW (Last-Write-Wins) 冲突解决**: 比对本地 Room 数据库与云端 JSON 相同 ID 笔记的 `updatedAt` 时间戳，以更新者为准进行状态合并；
  2. **墓碑标记 (Tombstone) 传播**: 保证单端执行软删除 (`isDeleted = true`) 后能够准确传播至所有端；
  3. **标签与双向关系重建**: 自动解析远端标签并在本地 Room 建立映射与交叉索引；
  4. **图片附件增量同步**:
     - 比对云端 `/Lozify/images/` 与本地沙盒 `context.filesDir/images/` 差异；
     - 仅上传本地独有图片，仅下载远端新增图片，避免大文件重复传输。
