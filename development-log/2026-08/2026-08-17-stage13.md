## 🐛 踩过的坑与技术复盘

### 坑 #1: DAO 手写 SELECT 查询遗漏新字段导致 Room 映射为 null

**现象**:
数据库已成功执行 `ALTER TABLE tags ADD COLUMN icon TEXT`，并且更新方法也成功将 `icon` 写入了数据库，但是在侧边栏列表中读取出来的 `tag.icon` 始终为 `null`。

**根本原因**:
`TagDao.kt` 的 `getAllTags()` 使用了显式字段列举的 SQL 查询：
```sql
SELECT tags.id, tags.name, COUNT(note_tag_cross_ref.note_id) as usage_count 
FROM tags ...
```
在数据库实体增加 `icon` 字段后，手写 SQL 中遗漏了 `tags.icon`，导致 Room 在将 Cursor 反序列化为 `TagEntity` 时，`icon` 字段无法获得查询结果，默认填充了 `null`。

**解决方案**:
修改 `TagDao.kt` 的 SQL 查询，显式补充 `tags.icon` 字段：
```sql
SELECT tags.id, tags.name, tags.icon, COUNT(note_tag_cross_ref.note_id) as usage_count 
FROM tags ...
```

**关键教训**:
- 在使用 Room 关联查询或聚合统计查询时，如果有手写的 `SELECT a, b, c` 语句，一旦 Entity 发生迁移增删字段，必须同步更新 DAO 中的所有 SQL 语句。

### 坑 #2: Compose 内联标签 Placeholder 宽度固定导致中文标签截断或溢出

**现象**:
使用 `appendInlineContent` 渲染胶囊标签时，如果给 `Placeholder` 指定固定的宽度（如 `60.sp`），短标签（如 `#A`）两边留白过大，而长标签（如 `#极简卡片式笔记App`）文字会被严重截断或溢出。

**根本原因**:
Jetpack Compose 的 `InlineTextContent` 中的 `Placeholder` 必须在布局测量前提供具体的 `TextUnit` 尺寸（`width` 与 `height`），无法直接设置 `wrap_content`。

**解决方案**:
在 `RichTextUtils` 中实现字符编码感知（Char-Code Aware）的动态宽度计算函数：
```kotlin
fun calculateTagBadgeWidth(tagName: String): TextUnit {
    // 中文字符宽度约为 13sp，ASCII 字符约为 7.5sp，加上 # 前缀与水平内边距
    val charWidthSum = tagName.sumOf { if (it.code > 127) 13.0 else 7.5 }
    val totalWidth = 8.0 + charWidthSum + 12.0
    return totalWidth.sp
}
```
结合 `Text` 内部的 `fontSize = 12.sp` 与 `padding(horizontal = 4.dp)`，实现了精准自适应各长度中英文标签的内联胶囊效果。
