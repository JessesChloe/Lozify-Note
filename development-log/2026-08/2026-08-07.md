**Schema Design Highlights:**
- `NoteEntity`: 6 fields (id, content, createdAt, updatedAt, isPinned, isDeleted)
- `AttachmentEntity`: One-to-many with cascade delete, stores internal file paths only
- `NoteTagCrossRef`: Junction table with composite primary key (noteId, tagId)
- All timestamps stored as `Instant` (Java 8 Time API) with Room type converters

### Stage 2 关键 Bug 修复

#### 问题描述
用户在模拟器验收时发现：第 2 张长文本卡片成功截断显示省略号，但**没有显示蓝色"展开"按钮**。

#### 根因分析
原实现使用 `content.lines().size > maxCollapsedLines` 判断是否显示展开按钮：
- `content.lines()` 仅统计原始文本中的 `\n` 换行符数量
- 无法检测 Compose Text 因宽度限制自动换行导致的溢出
- 长段落文本即使没有换行符，也会因容器宽度自动折行超过 5 行

#### 修复方案
使用 Compose 官方 API `onTextLayout` 回调精确检测：

```kotlin
var showExpandButton by remember { mutableStateOf(false) }

Text(
    text = content,
    maxLines = if (isExpanded) Int.MAX_VALUE else maxCollapsedLines,
    overflow = if (isExpanded) TextOverflow.Ellipsis else TextOverflow.Visible,
    onTextLayout = { textLayoutResult: TextLayoutResult ->
        if (!isExpanded && textLayoutResult.hasVisualOverflow) {
            showExpandButton = true
        }
    }
)

if (!isExpanded && showExpandButton) {
    Text("展开", color = Color(0xFF4C88FF), modifier = Modifier.clickable { isExpanded = true })
}
```

**关键改进：**
- `textLayoutResult.hasVisualOverflow` 基于实际渲染结果判断
- 新增 `showExpandButton` 状态变量独立控制按钮显示
- 只有真实发生视觉溢出时才显示"展开"链接

private fun formatTimestamp(instant: Instant): String {
    val duration = Duration.between(instant, Instant.now())
    return when {
        duration.toMinutes() < 1 -> "刚刚"
        duration.toMinutes() < 60 -> "${duration.toMinutes()}分钟前"
        duration.toHours() < 24 -> "${duration.toHours()}小时前"
        duration.toDays() < 7 -> "${duration.toDays()}天前"
        duration.toDays() < 30 -> "${duration.toDays() / 7}周前"
        duration.toDays() < 365 -> "${duration.toDays() / 30}个月前"
        else -> "${duration.toDays() / 365}年前"
    }
}
