**文件路径：** `app/src/main/java/com/witte/lozify/core/common/TagUtils.kt`

**核心功能：**
```kotlin
// 正则表达式：匹配 #标签（支持中英文、数字、下划线）
private val TAG_REGEX = Regex("(?<=^|[\\s\\p{Punct}])#([\\p{L}\\p{N}_]+)(?=$|[\\s\\p{Punct}])")

// 提取所有唯一标签名
fun extractTags(content: String): List<String>

// 构建带蓝色高亮的 AnnotatedString
fun buildAnnotatedStringWithTags(
    content: String,
    tagColor: Color = Color(0xFF4C88FF),
    onTagClick: ((String) -> Unit)? = null
): AnnotatedString

// 检测文本是否包含标签
fun containsTags(content: String): Boolean

// 获取点击位置的标签名
fun getTagAtOffset(annotatedString: AnnotatedString, offset: Int): String?
```

**技术亮点：**
- Unicode 字符支持（`\p{L}\p{N}`）：中英文标签均可识别
- 边界检测（`(?<=...)`）：避免误匹配单词内部的 `#`
- ClickableAnnotation：为每个标签添加点击交互能力

## 阶段二：关键 Bug 修复

### 🐛 Bug 描述

**现象：** 点击任何标签筛选后，主页立刻显示 EmptyState（"还没有任何笔记"），无法筛选出包含该标签的笔记。

**验证环境：** Android Studio 模拟器实机测试

---

### 🔍 根因分析

**问题定位：** `NoteRepositoryImpl.getAllNotes()` 返回的 `Note` 对象 **`tags` 字段为空列表**。

**代码缺陷：**
```kotlin
// NoteRepositoryImpl.kt:41-51 (修复前)
override fun getAllNotes(): Flow<List<Note>> {
    return noteDao.getAllNotes().map { noteEntities ->
        noteEntities.map { noteEntity ->
            buildCompleteNote(noteEntity.id)  // ❌ 返回简化版本，tags = []
        }
    }
}
```

**触发链路：**
```
用户点击标签筛选
  ↓
HomeViewModel 执行 note.tags.any { it.id == selectedTagId }
  ↓
note.tags = [] → 返回 false
  ↓
所有笔记被过滤 → EmptyState
```

---

### ✅ 修复方案（双保险机制）

#### 修复 1: NoteRepositoryImpl.getAllNotes() 填充 tags 字段

**文件：** `data/repository/NoteRepositoryImpl.kt:41-51`

```kotlin
override fun getAllNotes(): Flow<List<Note>> {
    return noteDao.getAllNotes().map { noteEntities ->
        noteEntities.map { noteEntity ->
            val tags = tagDao.getTagsForNote(noteEntity.id)
            noteEntity.toDomainModel().copy(
                tags = kotlinx.coroutines.runBlocking { tags.first() }.toDomainModels()
            )
        }
    }
}
```

**效果：** 每个 `Note` 对象现在包含完整的 `tags` 列表（从 `NoteTagCrossRef` 关联表查询）。

---

#### 修复 2: HomeViewModel 双保险筛选逻辑

**文件：** `presentation/home/HomeViewModel.kt:51-75`

```kotlin
val filteredNotes = if (selectedTagId == null) {
    allNotes
} else {
    val selectedTag = allTags.find { it.id == selectedTagId }
    allNotes.filter { note ->
        // ✅ 主策略：ID 精确匹配
        val hasTagById = note.tags.any { it.id == selectedTagId }

        // ✅ 兜底策略：内容正则匹配（忽略大小写）
        val hasTagByContent = selectedTag?.let { tag ->
            note.content.contains("#${tag.name}", ignoreCase = true)
        } ?: false

        hasTagById || hasTagByContent
    }
}
```

**双保险机制：**
1. **主策略（hasTagById）**：依赖数据库 `NoteTagCrossRef` 关联表的 ID 匹配
2. **兜底策略（hasTagByContent）**：直接在 `note.content` 中搜索 `#标签名`
3. **OR 逻辑**：任一策略匹配即视为成功，绝对杜绝"全为空"的情况

**防御性编程优势：**
- 即使数据库关联表意外缺失，仍能通过内容匹配兜底
- 忽略大小写匹配（`ignoreCase = true`）提升用户体验
- 性能优化：优先使用高效的 ID 匹配，内容匹配作为备用

#### 踩坑与解决

- **加固**：HomeViewModel 增加内容匹配兜底逻辑，双保险确保筛选成功

#### 未来优化方向
- **性能优化**：考虑使用 Room 的 `@Transaction` + `@Relation` 注解自动填充关联数据
- **缓存策略**：频繁访问的标签列表可考虑增加内存缓存层
- **FTS 搜索**：未来可集成 Room FTS4 全文搜索提升标签检索性能
